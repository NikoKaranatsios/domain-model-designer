# UML scope and validation

This product designs UML data structures using the notation and semantics in [OMG UML 2.5.1](https://www.omg.org/spec/UML/2.5.1). It supports a defined subset; it is not an OMG-certified UML tool, a complete UML metamodel, an XMI interchange implementation, or a formal proof of a service's business rules.

**Check** reviews every class, including hidden areas. It reports undefined types, ambiguous inheritance, incompatible redefinitions, included-field collisions, missing reference identifiers, composite references without component mapping, and incompatible foreign-key types. Imported incomplete definitions remain editable drafts with visible findings. Passing these checks means no issue was found by these specific checks; it does not certify an arbitrary model as correct.

PK is the product's relational interpretation of UML `isID`. UK means a single-attribute database uniqueness convention, including uniqueness among present values for optional attributes. It is **not** UML collection `isUnique`, which governs duplicate values within a property's collection. FK names a referenced class; composite-key mappings require explicit constraints. Unique constraints and business rules are preserved as text, not parsed SQL or executed OCL. A relational implementation must translate and enforce them, including null and collation policies.

Domain areas are visual groups. They do not declare UML packages, bounded contexts or runtime services. Included value types flatten reusable fields by a product convention; they do not imply UML inheritance. UUID, Decimal, DateTime and other declared primitives extend the type vocabulary. Collection ordering, qualifiers, association classes, n-ary associations, operations, behavior, visibility, default values and the full UML profile system are outside this format. Import rejects known unsupported modifiers rather than dropping their meaning.

The diagram may show only key properties or the first 128 properties per card, with an explicit count of omitted attributes. Class details and exports retain all supported properties. Inherited attributes appear in details and exports; their omission from a subclass card does not remove them. Saved connection paths are reused only when they attach to the correct classes and avoid every card interior. Relationship annotations are placed outside cards and other labels; endpoint annotations stay within 40 model-space pixels of their preferred position to avoid suggesting another relationship; an annotation that cannot fit nearby is hidden. Selecting a relationship exposes its complete end roles and bounds in the details panel, and exports always preserve them. Hidden notation never changes the underlying model.

Regression tests cover the codec, editor, compiler, importer, marker direction, recursive composition, interface generalization, incomplete definitions, legacy parents, saved-route attachment, property limits and the fictional events graph. Business constraints, finite-instance satisfiability, transactional concurrency, money calculations, authorization and actual provider processing remain responsibilities of the implementing service.
